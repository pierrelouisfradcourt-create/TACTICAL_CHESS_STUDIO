# Chess TCG — Revue d'architecture / contestation (2026-07-06)

status: DOCUMENTED_ONLY · déclenché par consigne Pierre « conteste la roadmap/archi avec les infos à jour + recherche web ».
Recherche web menée en tranche 2. Décisions ci-dessous appliquées au code.

## Décision 1 — Pipeline de résolution explicite (adopté dès T2)
**Contestation** : le `resolve()` à mutation directe de T1 ne tient pas quand arrivent traversée (N contre-attaques
ordonnées le long d'un chemin), riposte (événement réactif), puis BRAWL/triggers (T3+).
**Décision** : passer à un **pipeline explicite ordonné** `Action → étapes → journal d'événements`, aligné sur le
**pipeline 17 étapes du canon** (`04_RNG…`/RECOVERY §6). Le journal d'événements est retourné (observabilité + graine de
**replay** pour le simulateur de balance).
**Appui recherche** : le pattern command/event-queue est le standard des jeux tactiques tour-par-tour déterministes,
précisément parce qu'il rend les actions sérialisables → rejouables → simulables (et networkables plus tard).
Réf : Game Programming Patterns (Command), Cloaked Games (function queue), Outscal (turn-based architecture).

## Décision 2 — GDScript typé (confirmé), C# différé pour la sim lourde
**Contestation** : « générateur + simulateur en GDScript » risque d'être lent pour de gros batchs.
**Décision** : **rester GDScript** pour le moteur + le jeu (typé partout — jusqu'à ~59 % plus rapide que non typé, et
**exportable web**, ce que C# ne permet PAS en Godot 4.6). Le **simulateur batch / générateur** (seul cas « sim lourde »)
sera réévalué en **C# ou outil offline** *au moment où le volume l'exige* — pas en v1 (50-500 parties = trivial).
**Appui recherche** : pour la logique de jeu la différence GDScript typé / C# est invisible ; C# ne gagne que sur les
boucles numériques serrées / sim massive ; C# non exportable web en 4.6.

## Décision 3 — Tests : harnais maison maintenant, gdUnit4 au CI
**Décision** : garder le harnais headless maison (zéro dépendance) pour avancer ; **migrer vers gdUnit4** (rapport JUnit
XML, action CI officielle, `--headless --import` puis run) quand on câble le **CI auto-hébergé** du studio (IMP-237).
**Appui recherche** : gdUnit4/GUT = standards Godot 4 avec intégration CI headless (import warm-up + exit-on-fail).
