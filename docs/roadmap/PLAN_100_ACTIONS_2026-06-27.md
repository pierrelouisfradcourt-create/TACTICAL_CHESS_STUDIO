## 0. Thèse stratégique (lire avant la liste)

L'audit l'a montré : **le studio est une machine de gouvernance solide posée sur une coquille produit vide.** Pour produire « en masse », ce ne sont pas 100 features qu'il faut, mais **5 leviers démultiplicateurs**, puis du contenu qui s'y branche :

1. **Généraliser la factory** — aujourd'hui `IRCompiler.REQUIRED_ENTITIES` est figé sur les 4 entités Snake (`studio_core/compiler/ir_compiler.py:15`). Tant que ce verrou tient, « factory » = reskins de Snake. **Tout le reste en dépend.**
2. **Fermer la boucle prompt → artefact** — `run_chain.py` produit un *prompt*, pas du code ; `kaizen_autoloop` est la seule boucle qui émet des artefacts, mais elle est dormante (director read-only). Le moteur LM (Qwen2.5-14B local) est déjà là, inutilisé pour générer du jeu.
3. **Extraire & partager le design system** — le cockpit a un vrai DS maison (24 tokens CSS, `.card/.pill/.stat-blk`, `autopilot.py:2984`), mais enfermé dans une string Python de 4020 lignes. Chaque nouvel écran/jeu repart de zéro.
4. **Réutiliser l'oracle de balance** — `headless_sim.py:219-251` valide automatiquement n'importe quel IR (survie, timeout, mort-mur…). C'est la **brique qualité la plus scalable** déjà présente, et le futur gate de clôture des IMP de contenu.
5. **Industrialiser le contenu** — registry de jeux, mutateur d'IR, pipeline d'assets : zéro existe aujourd'hui (les 10 `variants/` sont écrits à la main et orphelins).

Les 100 actions sont ordonnées pour que **les 5 leviers viennent en premier** (Vague 0-1), parce qu'ils multiplient le ROI de tout ce qui suit.
