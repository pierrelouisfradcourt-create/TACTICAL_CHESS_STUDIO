1. IDENTITE DU PROJET
1.1 Vision globale
Tactical Chess Studio est un laboratoire de decouverte de jeux tactiques par intelligence artificielle. Son architecture en couches vise a partir d'un moteur d'echecs pur pour evoluer vers un systeme de generation autonome de jeux tactiques equilibres.

Le projet repose sur deux branches paralleles distinctes :
Tactical Chess (design de jeu) — un jeu de plateau tactique inspiré des echecs, avec systeme RNG, draft, factions et PV par piece
TacticalChessPureLab (labo ML) — un moteur Rust + pipeline Python PyTorch pour entrainer une IA jouant aux echecs et, a terme, a des variantes

1.2 Identite du jeu — Tactical Chess
Tactical Chess est un jeu tactique competitif sur echiquier 8x8. Il combine :
la structure strategique des echecs classiques
un systeme RNG de generation d'unites par budget de puissance
une phase de draft par factions
des attaques geometriques et des altérations d'etat
un système de pression progressive du roi

Le jeu se situe entre : echecs modernes / auto-battler strategique / tactical RPG / TCG draftable.
Inspirations explicites : echecs classiques, Teamfight Tactics, Magic the Gathering, Tactical RPG, jeux d'escarmouche.

1.3 Identite du labo ML — TacticalChessPureLab
Le labo ML est distinct du jeu. Son objectif actuel (Phase 9) est :
PURE CHESS AI TRAINING LAB
Pipeline operationnel :
Rust engine
→ Stockfish teacher (teacher_uci)
→ dataset generation (JSONL)

3.2 Formules canoniques
Degats directs
directDamage = max(1, attackerATK - defenderARM)

Riposte
retaliationDamage = max(1, defenderATK - attackerARM)

Traversee
traversalDamage = max(1, controllerATK - moverARM)
Baseline observee : ~4.68 morts de traversee / partie en moyenne

BRAWL
brawlDamage = max(1, attackerATK - defenderARM)
Baseline observee : ~57.8 degats BRAWL moyens / partie

Pression du roi
kingPressure =
  directThreat
  + floor(supportingAttackers / support_divisor)
  + floor(blockedEscapes / blocked_escape_divisor)
  + brawlPressureContribution

Collapse du roi
collapse if kingPressure >= kingHP + pressure_threshold_bonus - fatigueReduction

Fatigue de pression
fatigueReduction: demarre a fatigue_start_turn
+1 tous les fatigue_step tours, max fatigue_max_reduction

3.3 Pipeline runtime canonique
select action
→ legality check
→ path build
→ traversal
→ arrival
→ direct attack
→ retaliation
→ cleanup dead
→ BRAWL
→ cleanup dead
→ pressure recompute

→ timeout adjudication if needed

4. GAME DESIGN — CROWN TACTICS V1
4.1 Structure de base
Plateau : 8x8
2 joueurs
Objectif : echec et mat du Roi OU annihilation totale

4.2 Roi
10 PV / 2 DEF / 2 PM
Peut etre attaque
Echec : une unite ennemie peut l'attaquer au prochain tour
Echec et Mat : aucune case sure + aucune defense possible

4.3 Systeme global d'unite
Chaque unite : PV / ATK / DEF / PM / Niveau (1→3)
Combat : degats = ATK - DEF (min 1)
1 attaque par tour
+1 niveau par kill, niveau max = 3
Niveau 2 : choix de classe / Niveau 3 : classe avancee

4.4 Draft
Budget : 25 points
1 Roi obligatoire (gratuit)
3 factions disponibles + unites neutres autorisees
Max 1 unite elite (Reine ou equivalent)
Max 2 unites speciales, minimum 4 unites

8. REGLES IMPLICITES CRITIQUES
8.1 Ordre attaque → mort → prise de case
1. calcul degats
2. application degats
3. si HP <= 0 : suppression de la piece cible
4. l'attaquant prend la case
5. increment kills
6. check promotion
Si la cible survit : pas de prise de case.

8.2 Promotion — moment exact
promotion resolue immediatement a l'evenement declencheur
la nouvelle piece remplace le pion sur la case
etat initial :
  canAttack = false
  canBrawl = true
  canControl = true
au tour suivant : canAttack = true

8.3 Empilement des buffs/debuffs
attaque finale = attaque de base + bonus allies - malus ennemis
attaque minimale = 1
Regle de stack : un seul buff de meme nature compte, un seul debuff de meme nature compte. Sinon la ligne de pions devient le moteur dominant.

8.4 Invocation
invocation uniquement sur case libre adjacente a l'invocateur
si la case devient occupee avant validation : echec
les invocations ne peuvent pas etre promues
meme si elles atteignent le fond / tuent

8.5 Root / Cavalier
root : bloque seulement l'action/mouvement
root n'altere pas le pattern du cavalier
Distinction : effet qui empeche d'agir = autorise. Modification de pattern / portee = interdit.
