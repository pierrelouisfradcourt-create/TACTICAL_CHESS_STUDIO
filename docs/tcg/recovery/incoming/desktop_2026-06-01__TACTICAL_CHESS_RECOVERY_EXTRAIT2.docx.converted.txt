2.2 Controle des cases — Regle fondamentale
une piece controle exactement les cases ou elle pourrait capturer une piece ennemie
Consequences directes :
Controle = menace = influence BRAWL
Le pion ne controle que ses diagonales d'attaque (pas la case devant lui)
Les pieces glissantes s'arretent a la premiere piece rencontree
Le blocage de ligne : Tour en A1, piece en A3 → controle A2+A3 seulement

2.3 Contre-attaques — Regles detaillees
Chaque fois qu'une piece traverse une case controlee par l'ennemi → contre-attaque immediate
Chaque controleur de la case peut contre-attaquer (cumul possible)
Les contre-attaques utilisent l'attaque finale reelle (buffs + debuffs + armure)
Si la piece meurt pendant la traversee → mouvement stoppe immediatement
Le pion double-move est traite case par case pour les contre-attaques

Formule de damage :
damageTaken = max(0, incomingDamage - armor)

2.4 Cavalier — Regles speciales
Controle normalement ses cases de capture
Contre-attaque comme toute piece
Ignore les menaces PENDANT la traversee
Subit les contre-attaques sur la case FINALE uniquement
Vaut 2 defenseurs dans le calcul BRAWL

2.5 Roque
Autorise si : roi jamais deplace, tour jamais deplacee, cases intermediaires libres.
⚠ Le roque ne doit pas devenir punitif a cause des contre-attaques.

3.2 Formule de pression du roi
kingPressure =
  directAttack                         // somme ATK des pieces menaçant la case du roi
  + ceil(support / 2)                  // soutien des attaquants
  + kingDebuffs                         // debuffs actifs SUR LE ROI uniquement
  + brawlPressure                       // contribution BRAWL local
  + ceil(blockedEscapes / 2)            // cases de fuite bloques

Regles importantes :
Seuls les debuffs sur le roi comptent — pas les buffs des attaquants
Pas des debuffs sur les defenseurs
Pas des auras globales
Si kingPressure >= threshold → roi mate par pression

4. BRAWL — SYSTEME AVANCE
4.1 Regles BRAWL
si attackers > defenders → BRAWL
brawlDamage = max(1, attack - 1)
puis armure appliquee

Le cavalier compte comme 2 defenseurs
Lecture simultanee, ecriture sequentielle sur snapshot
Les pieces deja mortes apres l'action active ne BRAWL pas
Sorts resolus AVANT le BRAWL : pieces tuees par sort absentes du BRAWL
Root avant BRAWL : piece rootee retire sa contribution BRAWL offensive

4.2 Pipeline BRAWL complet
1. snapshot du board
2. pour chaque cible dans snapshot :
   a. calculer attackers
   b. calculer defenders (cavalier = 2)
   c. appliquer BRAWL si attackers > defenders
3. appliquer les degats
4. cleanup des morts
5. mise a jour telemetrie

5.2 Regles de stack (tous statuts)
Par defaut : non-stack — reapplication = refresh de duree
Cap alternative toleree : max 2 du meme type
Couleur/camp immuable : une piece ne change jamais de couleur apres creation
Identifiant unique : chaque piece a un id immuable — liens (invocation, suppression) passent par cet id

5.3 Regles d'interaction statuts / pression du roi
Si la regle globale retenue est '+1 par debuff sur le roi' :
root, stun, freeze sur roi → forte augmentation de pression
silence sur roi → augmentation de pression (desactive auras/passives)
disarm, fear sur roi → augmentation de pression
charm sur roi → augmentation enorme (quasi-max)
poison, burn sur roi → depend de la regle globale choisie
regen sur roi → ne reduit pas directement kingPressure

⚠ Choisir UN modele pour la pression statuts : soit 'tous les debuffs comptent', soit 'seulement les controles durs'. Ne pas mixer.

5.4 Statut : root — Detail
Bloque mouvement et action active
Ne modifie jamais le pattern du cavalier
Root sur cavalier = bloque l'agir, pas le pattern
Pièce rootée : ne contre-attaque pas (V1 recommande)
Pièce rootée : retire contribution BRAWL (V1 recommande)

5.5 Statut : silence — Detail
Desactive : auras non-stat, activated abilities, triggers, summon ability
N'enleve pas le mouvement de base ni ATK/HP/ARM natifs
Contre-attaque de base autorisee, mais riders ability supprimés
BRAWL de base autorise, bonus ability supprimés

5.6 Statut : disarm — Detail
cannotAttack = true
deplacement autorise
Pas de contre-attaque
En BRAWL : corps present mais pas de contribution offensive
Recommandation V1 : disarmed piece ne projette pas de controle

5.7 Statut : charm — Detail
⚠ Charm n'a pas ete stabilise. Implementation recommandee V1 : equivalent de stun.
Ne JAMAIS changer la couleur de la piece
Ne pas changer la propriete permanente
Duree : 1 tour maximum

5.8 Statut : destroy — Restrictions
Bypasse HP et armure
Ne doit JAMAIS etre un rider de BRAWL par defaut
Ne doit presque jamais etre en contre-attaque generique
Prohibe en standard king runtime si cible = roi

7.4 Attaque — Pipeline
1. computeAttackValue(attacker, target)
2. apply damage to target
3. si target survit : riposte possible
4. si target meurt : attaquant prend la case
                     attacker.kills += 1

attack → cleanup → promotion → suite du pipeline

8.2 Decomposition complete de l'evaluation
score =
  material
  + center                       (knight > bishop > queen > pawn > rook)
  - danger                       (dangerMap[x,y] * weight)
  + kingPressureInflicted * 5-12
  - ownKingPressure * 5-12
  + supportNetwork
  + defendedAttackerBonus        (+3-8 si attaquant soutenu pres du roi)
  + escapeDenial                 (+3 par case de fuite du roi bloques)
  + promotionPotential
  + summonUtility
  + fusionValue
  + retreatSafety                (+2-6 si echap zone mortelle)

11. SYSTEME DE FUSIONS
11.1 Regles generales
Action complete : remplace move/attack (pas en plus)
Deux pieces alliees adjacentes
La piece fusionnee est plus forte mais plus exposee (moins de corps sur plateau)
Une piece fusionnee est une cible strategique : plus forte = plus ciblable

11.2 Fusions les plus compatibles

11.3 Fusions a eviter
Fusions entre pieces lourdes completes (pattern trop universel)
Roi + reine — reservee au cas special Alien uniquement
Tout ce qui serait meilleur en ATK + DEF + mobilite + couverture simultanement
