# PROJECT IDENTITY

Tactical Chess Studio is an **AI Game Discovery Laboratory**. Its documented long-term purpose is to discover new tactical board games through a modular pipeline that goes from rules and validation to simulation, telemetry, evaluation, evolution, and discovery. The official architecture requires a deterministic core engine separated from simulation, validation, agents, telemetry, and discovery systems.

# REAL CURRENT MILESTONE

The real current milestone is:

```text
PURE CHESS AI TRAINING LAB
```

Not yet “game discovery machine.”

Reason: the active branch focus is PureLab, meant to stabilize a real chess research environment before reconnecting broader discovery systems. The documented path is incremental complexity, and the user’s validated loop has already reached: Rust engine build, Stockfish teacher, `teacher_uci`, dataset example generation, PyTorch training, checkpoint generation, and a neural tournament framework command. That places the project past generic engine prototyping, but before real neural match play and before integrated discovery.

# ARCHITECTURE RISKS

The main risks are structural, not conceptual.

First, **repo ambiguity**: the repository contains active code, historical prototypes, patch archives, backups, and documentation bibles together. That makes it easy for future AIs or developers to mistake scaffold code for integrated runtime code. 

Second, **cross-layer leakage**: the final architecture explicitly says the core engine must remain deterministic and must not absorb telemetry, discovery, or mutation logic. Any rushed evolution could violate that boundary. 

Third, **false confidence from framework commands**: a command compiling and printing a report does not prove full neural gameplay or valid Elo. That is especially important for `neural_tournament`, which appears ahead at the command level but still behind at the gameplay-inference level.

Fourth, **move encoding risk**: if teacher dataset labels, training targets, inference outputs, and legal move filtering do not use the same move vocabulary, the neural agent cannot become a real player even if training succeeds.

Fifth, **premature discovery work**: the project docs are explicit that chess is the initial environment and that assistants should focus on missing or broken components without unnecessary redesign. Jumping to mutation/QD now would increase fragility before the AI lab is stable.

=== CRITICAL SYSTEM CONTRACT ===

SHARED MOVE VOCABULARY

move_vocab.py is a system-wide source of truth.

All components MUST use the same mapping:

UCI move string
→ move index
→ dataset policy target
→ training target
→ inference logits
→ legal move masking

Any change to move representation must remain compatible across:

- teacher_uci_runner.rs
- dataset_loader.py
- train.py
- infer_policy.py
- neural_agent.rs

Violation of this contract will silently corrupt learning.

This is a critical integrity constraint.
