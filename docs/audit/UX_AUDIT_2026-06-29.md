## 1. EXECUTIVE SUMMARY — état réel vs vision

**Vision affichée :** un « studio de jeu autonome » avec cockpit unifié, council multi-LLM, usine à jeux, et un moteur d'échecs qui s'auto-améliore.

**Thème dominant (confirme l'audit 2026-06-27 en mémoire) :** *surface affichée > surface câblée*. Le cockpit est un dashboard de développeur solo riche en chrome, pauvre en boucle d'action fermée. L'écart avec Linear/Vercel se joue sur **fiabilité réseau**, **fraîcheur visible**, **unification** (1 cockpit, 1 design system, 1 scheduler), et **boucles d'action** (council, jeux).

**Verrou stratégique :** l'autonomie réelle est bloquée par l'ELO rouge (FAIL). Tant que la lane IA (IMP-161/162/163) ne lève pas ce verrou, l'autoloop ne tourne pas — donc « cockpit joli » et « studio autonome » sont deux chantiers découplés. **Le chemin le plus court vers un livrable concret est la lane JEUX (IMP-189→190).**

## 3. UX actuelle — inventaire + 10 failles

### Cadre technique (corrige le brief)
`autopilot.py` n'est **pas Flask** : `http.server.BaseHTTPRequestHandler` brut (`:7567`), routage cascade `if/elif self.path` dans `do_GET` (`:7598`) / `do_POST` (`:8129`) / `do_DELETE` (`:8686`), `ThreadingTCPServer` (`:8695`), port **7331**. Frontend = **SPA monolithique** `HTML = r"""..."""` (`:2982`), ~3500 lignes HTML+CSS+JS inline, servie sur `/`.

### Inventaire — 3 UIs non unifiées
1. **SPA autopilot.py** — sidebar 20 pages (`:3315-3350`) : Cockpit, Council, Vision, Pilote, Chaînes, Logs, Mémoire, Idées, Chain Map, Roadmap domaines, Métriques, Dataset & IA, Agents, Ligue, Moteur, Design, Roadmap jeux, Config, Studio OS, Workflow IMP.
2. **studio_canvas.html** — dashboard read-only autonome, poll gateway `:8766`, 3 colonnes (ELO/Oracles/meta), gate modal HMAC.
3. **studio_cockpit_v2.html** — **explicitement obsolète** (`:2-8` « sera deprecie, ne pas etendre ») mais toujours servable. Canonique annoncé : `studio_v2_ux/studio_cockpit.html`.
4. **canvas_gateway.py** — micro-gateway FastAPI port 8766 (`/api/meta`, SSE `/api/meta/stream`, `/api/gate/{id}` HMAC, `/api/director|factory|neural|openclaw`).

### Live vs polling vs statique
- **SSE (2 seulement)** : autoloop terminal (`:6547`, **`onerror` ferme sans reconnexion** `:6556`) ; canvas meta stream (reconnexion `setTimeout 30s`). `studio_canvas.html` n'utilise PAS le SSE dispo (poll 5s).
- **Polling (~13 timers)** : horloge 1s, LM 15s, escalation 10s, watcher 15s, proposals 30s, dedup 30s, next-action 60s, ledger 30s, health 30s, staleness 1h, autoloop 15s, cockpit 7 loaders/15s. Aucun chef d'orchestre, aucun backoff, `document.hidden` testé seulement sur le cockpit.
- **Statique (14 pages)** : chargées une fois dans `nav()`, figées tant qu'on ne re-clique pas. Aucun timestamp « last updated ».

## 4. Benchmark industrie — ce que font les vrais studios

**Top 5 patterns UX (Linear / Vercel Geist) :**
1. **Command palette `Cmd+K`** — chaque action au clavier, `/` filtre instantané (Linear, Geist Command Bar).
2. **Densité maîtrisée + hiérarchie** — haute densité info, faible bruit visuel, pas de sidebars chargées.
3. **Patterns d'action cohérents multi-voies** — même action par bouton / raccourci / menu / recherche.
4. **« Deployment Card »** (Geist) — statut + commit + branche + région + timing dans une carte dense = pattern canonique pour une liste d'IMP/builds.
5. **Microinteractions + feedback temps réel** — hover, tooltips, états de chargement confirmant la réactivité.

**Outils réels des studios :** Linear (issues, dev-first) · Perforce/Helix (assets binaires) · USD (échange pipeline) · **Mission Control** (open-source self-hosted SQLite, orchestration multi-agents — référence la plus proche du cockpit TCS) · `barichello/godot-ci` (CI builds Godot).

**Inspiration design TCS :** palette Geist (fond `#FAFAFA`/encre `#171717`, échelle gris 200 paliers, sémantique vert PASS/rouge FAIL/ambre BLOCKED en accents), **Geist Sans + Geist Mono** (mono pour IMP-IDs, verdicts, hashes HMAC). Layout : sidebar minimale par lane + zone centrale de « cards d'opérations » (1 IMP = 1 carte) + `Cmd+K` mappé sur le routing CLAUDE.md (oracle→smoke-check…) + bandeau oracle live. Densité Linear, et **séparation visuelle VÉRIFIÉ-oracle (couleur pleine) vs JUGEMENT-humain/fog (gris atténué)** — cohérent avec `/fog`.

## 5. Architecture `cockpit_server.py` (design)

**Contraintes vérifiées :** autopilot:7331 = raw http.server (NE PAS toucher). `canvas_gateway.py` (FastAPI:8766) = **template de référence** et porte DÉJÀ `/api/director|factory|neural|openclaw`. `ports.yaml` = SSOT (pris : 7331/8765/8766/1234 ; réservés 9000/9001). Doctrine IMP-191 : *le cockpit ne tape jamais 7331 — il lit les fichiers*.

> ⚠️ **Décision HumanGate (collision de périmètre) :** canvas_gateway:8766 implémente déjà les routes cockpit. Option **A** (recommandée) = extraire ces routes vers `cockpit_server.py` dédié, canvas_gateway revient à meta+gate strict. Option **B** = nouveau service distinct = doublon de surface (anti-doctrine). **Trancher A/B avant impl.**

**REST :** `/health` · `/api/cockpit/overview` · `/api/director(+/report,/schedule)` · `/api/ledger(+/{id})` · `/api/meta` · `/api/elo` · `/api/lichess` · `/api/factory` · `/api/events?limit=N` · `/api/ideas` · `/api/services` · `/api/runs(+/{id})` · POST `/api/director/refresh` · POST `/api/factory/run` · POST `/api/council/run` · POST `/api/gate/{id}`. *Lecture tolérante (fichier absent → `{available:false}` HTTP 200, jamais 500) ; `encoding='utf-8'` ; mutations passent `governor.check()` fail-closed (403 si BLOCK) ; HMAC vérifié → `hmac_valid:bool`.*

**SSE :** `/api/stream/meta` (mtime 2s) · `/api/stream/director` (2s) · `/api/stream/events` (tail-follow 1s) · `/api/stream/runs/{id}` (drain queue subprocess). Format `data:{json}\n\n` + heartbeat `:ping` 15s.

**Lit :** `IMPROVEMENT_LEDGER.yaml`, `director_status.json`, `director_report.md`, `director_schedule.json`, `studio_meta_latest.json`, `elo_match_latest.json(.hmac)`, `lichess_eval_latest.json(.hmac)`, `events.jsonl`, `ideas.json`, `factory/registry/registry.json`, `HUMANGATE_DECISION_LOG.yaml`. Probe TCP : 7331/8765/8766/1234.

**Délègue :**
- `director.py` → **import direct** `build_status(dry_run=True)` (pur, read-only) ; **subprocess** pour `/refresh` (écrit fichiers).
- `factory_loop.py` → **subprocess bg** `python -m studio.factory.factory_loop --ir PATH` (mutant + oracle long).
- `council.py` → **subprocess bg** `python scripts/council.py --brief --task-id ...` (3×120s, réseau, exit 10 = HumanGate).
- Pattern : `governor.check()` avant spawn → `asyncio.create_subprocess_exec` → registre in-memory `RUNS[run_id]` → réponse immédiate `{run_id}` → SSE log. **Lock fichier** `.studio_state/cockpit_runs.lock` contre double-lancement vs autopilot/autoloop.

**Archi FastAPI :** mono-fichier `scripts/cockpit_server.py` · `lifespan` (init `runs`, garde-fou port, cleanup subprocess) · `async` partout, ledger 218 IMP via `asyncio.to_thread` · bind `127.0.0.1` only · Pydantic pour POST (422 si payload vide) · `uvicorn --workers 1` (registre in-process).

**Coexistence :** port neuf **8770** (déclarer dans `ports.yaml` + program `supervisord.conf`). Aucun état mutable partagé (process distincts lisant les mêmes fichiers). Risques de collision read-during-write sur YAML/JSONL → lecture tolérante + cache dernier-parse-valide invalidé sur mtime ; double-écriture gate → atomique tmp+rename + idempotence par `decision_id` ; double-exécution council → lock fichier obligatoire.

## 7. CONSENSUS — PLAN / RED-TEAM / DIVERGENCE

### 7.1 PLAN (rôle Claude)
Construire `cockpit_server.py` (option A : extraire le cockpit de canvas_gateway) comme backend FastAPI:8770 read-files + délégation gouvernée, puis frontend SPA unifié 5 écrans avec couche fetch robuste, boucles d'action council+jeux, et design system Geist. Découpler explicitement « cockpit » (UX, peut avancer maintenant) de « autonomie » (bloquée par ELO rouge → lane IA). Prioriser en parallèle le chemin JEUX (IMP-189→190) comme premier livrable concret.

### 7.2 RED TEAM (rôle Qwen — ce que le plan rate)
- **Budget vs réalité solo.** Cockpit v3 = nouveau backend + nouveau frontend + décommissionnement. C'est un projet de plusieurs semaines pour un dev solo. Le plan sous-estime : réécrire une SPA de 3500 lignes inline n'est pas « refactor », c'est une réécriture. Risque : abandon à mi-chemin → **4e UI** qui s'ajoute aux 3 existantes.
- **Le hardcode n'est pas que cosmétique.** Si badge `12`/ELO `1424` sont en dur, c'est peut-être que **les endpoints réels n'existent pas**. Câbler « pour de vrai » peut révéler que la donnée n'est calculée nulle part → travail backend caché, non chiffré.
- **Option A casse studio_canvas.html.** Extraire les routes de canvas_gateway vers 8770 invalide les 2 HTML qui pollent 8766. Migration non planifiée = régression silencieuse.
- **Le verrou ELO domine tout.** Tant que `global_verdict=FAIL`, l'autoloop ne tourne pas — un cockpit magnifique pilote un studio à l'arrêt. Investir l'UX avant de lever l'ELO = polir le tableau de bord d'une voiture en panne.
- **`Cmd+K` mappé sur skills CLI** suppose un pont navigateur→CLI inexistant. Un bouton « lancer council » dans l'UI lance un subprocess 3×120s réseau — quelle UX pendant 6 min ? Le plan dit « SSE log » mais ne traite ni timeout, ni annulation, ni double-clic.
- **Mobile : faux besoin ?** Un cockpit de studio solo se pilote au desktop. Investir le responsive (P0-1) avant les boucles d'action peut être un mauvais arbitrage de priorité.

### 7.3 DIVERGENCE (rôle Gemini — 3 alternatives radicales)
- **(a) Minimaliste — « Tuer 2 cockpits, durcir 1 ».** Pas de cockpit_server.py. On supprime studio_cockpit_v2.html + studio_canvas.html, on garde la SPA autopilot, et on n'y fait QUE 4 patchs : couche fetch+timeout, suppression du hardcode (ou badge « mock »), fix lien mort `sos`, fix label mensonger. ~1 jour. Honnêteté immédiate, zéro réécriture.
- **(b) Ambitieuse — « Mission Control fork ».** On n'écrit pas notre cockpit : on adopte Mission Control (open-source, SQLite, orchestration multi-agents) et on branche council/factory/director dessus comme agents. Le cockpit TCS devient une instance configurée, pas du code maison. Gain : design pro gratuit, focus sur la logique studio. Risque : dépendance externe, courbe d'intégration.
- **(c) Inattendue — « Cockpit = fichiers + terminal, pas de web ».** Abandonner l'UI web. Le cockpit devient un TUI (Textual/Rich) + les skills CLA existants.
