# SECTION 4 - — Idea Dump (Non-canonical)
These are speculative or experimental ideas not required for the current encyclopedia, but potentially valuable.

1. Threat spectrum visualization layer
For simulation and design tools, generate heatmaps for:

movement danger

king pressure risk

traversal punishment

safe promotion lanes

board lock risk

This would make procedural debugging vastly easier.

2. Board archetype rotation
Create named board families:

Open

Choked

Diagonal-rich

Fortress

Broken-center

Lane-heavy

Then balance factions and generated units against board archetypes, not just one map.

3. Procedural role locking
When generating a piece, first assign a role archetype such as:

anchor

skirmisher

line-breaker

controller

finisher

support

Then generate stats and geometry inside that role’s allowed band. This reduces broken outliers.

4. Multi-axis rarity
Instead of one rarity, use hidden internal axes:

power rarity

complexity rarity

rule-bending rarity

That lets you make interesting but not overpowering cards, or powerful but easy-to-read cards.

5. “Design entropy” meter for set generation
Every generated set gets an entropy score based on:

status diversity

geometry diversity

role overlap

range spread

meta compression

Too low = repetitive
Too high = unreadable

This could become the central set-quality metric.

6. Simulation stress profiles
Run generated content through specialized stress suites:

open-board profile

congested-board profile

king-safety profile

attrition profile

summon-swarm profile

hard-control profile

This catches issues that average self-play may hide.

7. Shadow cost for board frustration
Some mechanics are mathematically fair but psychologically miserable. Add a hidden “frustration tax” to:

hard displacement

repeated freeze

forced ally attack

long-range denial

endless summon walls

This is often the difference between a technically balanced game and a good one.

8. Procedural faction DNA fingerprints
Every faction could be represented numerically by a fingerprint vector:

average range

average geometry width

status mix

summon rate

pressure rate

traversal strength

king-style bias

This makes overlap detection and future expansion much easier.

9. Content sustainability model
Given the project’s franchise ambition, define a content growth model:

number of factions sustainable before rotation

number of active status families

maximum new mechanics per set

complexity cap per expansion wave

This avoids long-term rules collapse.

10. Canonical “danger classes” for future design
All future mechanics could be tagged:

green = safe

yellow = needs simulation

orange = set-defining and risky

red = historically toxic combination class

This helps preserve the encyclopedia as a living design instrument rather than just a reference.
