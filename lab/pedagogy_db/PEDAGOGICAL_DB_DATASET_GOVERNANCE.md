# Pedagogical DB — dataset governance

This file links the pedagogical database work to the active PureLab dataset doctrine.

## Status

Current status: curated side dataset, not promoted main dataset.

Reason:
- the pedagogical database is useful now for targeted endgame / tactics / conversion work
- but main dataset promotion requires manifest-driven validation and benchmark support

## Priority order

Selection priority used for the current curated batch:
1. endgames
2. tactics
3. conversion

This priority is intentionally compatible with the current lab phase where conversion recovery matters and where pedagogical clarity beats prestige value.

## Selection doctrine

A game, fragment, or exercise belongs here only if it has direct pedagogical value for PureLab.

Preferred signals:
- clear technical ending
- visible tactical punishment
- readable conversion sequence
- useful defensive hold
- legible conclusion

Low-yield material should stay out:
- quiet prestige-only games with little teaching signal
- sterile repetitions
- long drift without pedagogical event
- unclear narratives

## Required narrative classes

Every future admitted item should map to at least one useful class:
- Build
- Tension
- Punish
- Convert
- Defend
- Conclude

Items that are only Drift should be rejected.

## Hard exclusions

These must never enter a promoted core dataset candidate:
- hard-cap terminations
- fake max-turn draws
- random primary trajectories
- broken or unknown provenance dominant items
- sterile repetition as a meaningful share
- long drift with no instructional story

## Promotion rule

The pedagogical DB may inform later dataset promotion, but must not overwrite the historical seed or silently become the main dataset.

Promotion requires:
- manifest present
- dataset validation passed
- strong provenance
- zero hard-cap contamination
- low sterile draw rate
- identifiable narrative classes
- benchmark support

## Metrics expected for future pipeline work

Minimum governance metrics expected:
- result_distribution
- useful_draw_pct
- sterile_draw_pct
- termination_mode_breakdown
- source_type_breakdown
- source_confidence_tags
- narrative_class_distribution
- motif_coverage_table
- keep_pct / weak_keep_pct / reject_pct
- manifest_present
- dataset_validation_pass

## Active lab alignment

This database is aligned with the active lab doctrine:
- active repo truth first
- curated data must remain traceable
- validation beats narrative optimism
- hard cap is lab-only and must never be taught as chess truth
- conversion-rich pedagogical material is currently favored
