## Constat structurant (racine de 3 des 4 failles)

La scène embarquée `main.tscn` (le jeu réellement lancé — `project.godot:14` → `run/main_scene="res://main.tscn"`) n'instancie qu'un seul nœud : `HUD` porté par `hud.gd` (`main.tscn:3,7-8`). Elle ne branche **ni** l'entrée (`input.gd`), **ni** la boucle de production (`auto.gd` — aucun `_process`/`Timer` dans tout le runtime), **ni** le rendu des chatons (`kitten_view.gd`), **ni** l'audio (`audio.gd`), **ni** le chargeur de contenu (`content.gd`). `hud._ready()` appelle `draw_hud(0.0, 0.0)` en dur (`hud.gd:21`) et rien ne le ré-alimente depuis `state.aggregate_rate()`. Le jeu embarqué affiche donc en permanence « 0 ronrons / 0 /sec », sans objet cliquable, sans chaton, sans son. `project.godot:5-7` l'admet dans le code même : « la wiremap gelée ne déclare AUCUNE ligne de coordination runtime … l'assemblage jouable complet n'a pas d'adresse déclarée ». Chaque système est prouvé **en isolation** ; l'intégration jouable n'existe pas.
