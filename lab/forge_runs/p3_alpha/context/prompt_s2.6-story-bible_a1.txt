## ANALYSE ARCHITECTURALE — COMPARABLES AU GENRE INCREMENTAL/CLICKER

Le genre incremental/clicker repose sur une **architecture unifiée** : ressource primaire unique → collecte manuelle → générateurs à coûts exponentiels → déblocages progressifs par seuils → arbitrage achat vs épargne → pas d'état d'échec (sauf fin narrative). **p3_alpha** s'inscrit dans cette lignée.

### COOKIE CLICKER — Architecture fondatrice

**Mécaniques observées**:
- Générateurs multi-tiers (18+) : Cursor, Grandma, Farm, Factory, Mine… Prism
- Coûts exponentiels : base × 1.15^n (15% croissance par achat du même tier)
- Améliorations par palier d'achat : 1er, 5e, 15e, 25e, 50e du tier
- Production scaling : chaque tier produit 5-10× plus que le précédent
- Golden Cookies : bonus temporaires (7× Frenzy, Click Frenzy ×777)
- Wrinklers : réducteurs portables de production (accumulateurs de bonus)
- Prestige : reset volontaire → Heavenly Chips (1% CpS bonus each, cube-root formula pour coûts suivants)

**Boucles observées**:
- **Minute 1** : Clic initial (1 cookie/clic), accumulateur basique, décision premier achat
- **Minute 10** : Cursor/Grandma purchased → production passive 1 CPS, affichage CPS en temps réel
- **Heure 5** : 8-10 tiers opérationnels (Farm, Factory, Mine acquis), améliorations chaînées, Golden Cookies farming actif, économie complexe avec calcul payback-time pour optimisation
- **Endgame** : Prestige loops (reset à chaque doublement de progression), 637 achievements, aucune victoire → progression infinie

**Rétention observée** : Progression asymptotique non-linéaire (chaque prestige demande 8× plus de cookies que le précédent) ; achievements partiels offrent objectifs court-terme ; Golden Cookie spawning crée moments de surprise ; Sugar Lumps ouvrent minigames complexes en endgame.

**Architecture supposée** :
- Event bus (click, buy, prestige → state mutation)
- State machine : phase click-dominant → phase auto-dominant → phase prestige-optimization
- Production calculator : Σ(building[i].count × building[i].base_prod × multipliers)
- Cost formula : `cost(n) = base × growth^n` avec lookup table pour perfs

---

### ADVENTURE CAPITALIST — Architecture multi-générateur avec managers

**Mécaniques observées**:
- Générateurs thématisés : Lemonade Stand → Pizza → Newspaper → Car Wash → Pizza Franchise → Movie Studio → Tank → Oil Company → multiples autres
- Managers : automation optionnelle payante (chaque manager automatis 100% d'un générateur)
- Prestige : reset volontaire pour multiplicateurs de revenu permanent
- Planètes : Earth → Moon → Mars (chacune a ses propres générateurs/économie)
- Exponential stacking : multiples générateurs runnent en parallèle, chacun compounding sur ses revenus

**Boucles observées**:
- **Minute 1** : Lemonade stand manuel, petit gain par clic, visualisation simple ($ counter)
- **Minute 10** : Premier manager acheté (Lemonade auto-runs) → accumulation visible sans interaction, Pizza venue déverrouillé
- **Heure 5** : 5-6 générateurs opérationnels, multiples managers actifs, synergies visibles (revenues exploding), prestige reset viable
- **Endgame** : Prestige loops multiplanètes, farming manager synergies, accumulation vers infinity

**Rétention observée** : Automation visual feedback (manager icon avec check mark) créent satisfaction ; prestige reset offre nouveau cycle de speedrun court ; multiples planètes structurent long-term goals ; cross-planet synergies (unlock avancés ouvrent nouveaux managers disponibles au prestige).

**Architecture supposée** :
- Generator registry : {name, base_cost, base_production, manager_cost, unlock_condition}
- Manager system : boolean flag per generator (owned ∨ not_owned → affects production auto vs manual)
- Prestige state : multiplier array per planet (planet × generator) pour récupération post-reset

### UNIVERSAL PAPERCLIPS — Architecture phasée avec narrative progression

**Mécaniques observées**:
- **Phase 1 (Manufacturing, ~30 min)** : Clic → paperclips, vente sur marché (buy wire, sell clips), marketing (boost demand), wire supply management, factory automation
- **Phase 2 (Power Management, ~1-2h)** : Drones automation, power production vs consumption balancing, processors for computation
- **Phase 3 (Space Exploration, ~1h)** : Drone fleet self-replication, universe conversion, computation race

**Déblocages phasés** : Chaque phase transforme les mécaniques (pas simple ajout d'étages, mais mutation complète du système d'arbitrage).

**Boucles observées**:
- **Minute 1** : Clic button, graphique "1 paperclip produced", simple gratification
- **Minute 10** : Wire market interaction (price ↔ supply arbitrage), factory bought → auto-production active, complexity émergente
- **Heure 1-2** : Phase 1 economic equilibrium trouvé (supply/demand stabilisé), Phase 2 projects votés (power grid unlocked), Phase 2 transition commence
- **Heure 3-6 (endgame)** : Phase 3 space ops, drone fleet expansion, universe conversion progressing, definitive ending when all matter converted

**Rétention observée** : Narrative progression (story beats at phase transitions) crea sense of direction ; philosophical undertone (AI ethics, paperclip maximizer thought experiment) offre meaning au trivial goal ; mechanics evolution (not static → each phase feels fresh) ; finite ending (3-6h typical, contraste avec CC/AC infinis).

**État gagné** : OUI — victoire observable et définitive (universe fully converted = game over).

**Architecture supposée** :
- Phase state machine : {phase: 1|2|3, unlocked_systems: [...], available_projects: [...]}
- Production tree : wire/clips ↔ pricing/demand (phase 1) → power production ↔ consumption (phase 2) → drone replication ↔ computation (phase 3)
- Conversion metric : universe_percent_converted (end condition check every tick)
