## World Scan — p2_alpha (s2-worldscan / run1)

### OBSERVATION D'ARCHITECTURE EXTERNE

Pour comprendre l'assemblage de boucles et la rétention d'un prototype arcade avec progression, j'ai examiné trois titres comparables attestés publiquement :

#### **1. Tetris Effect (Blue Planet, Monstars)**
**Boucles observées** (via gameplay Twitch + doc design) :
- **Minute 1** : joueur place les premières pièces, comprend la grille 10×20, une ligne complétée revient immédiatement. Score monte par paliers (dix points/ligne). Feedback sonore et visuel brut.
- **Minute 10** : joueur développe une stratégie de stack ; les pièces accélèrent progressivement. Musique réactive épouse la cadence de jeu. Première vague de GameOver potentielle (surcharge colonne).
- **Heure 5** : joueur maîtrise des combinaisons (Tetrises = 4 lignes d'un coup, multiplicateur 4×). Économie des points saturée (plafond de score atteint par des boucles hyper-optimisées). Endurance devient facteur : fatigue visuelle, décision sous stress temporel croissant.
- **Endgame** : GameOver ou réinitialisation en NG+ (niveau suivant). Pas de stato persistant entre runs sauf score global highscore. Objectif clairement défini : rester vivant le plus longtemps possible.

**Rétention** : Tetris fonctionne sur deux axes : (a) perfection motrice (exécution sans erreur), (b) progression mesurée (vitesse ↑ = difficulté ↑ = fierté du joueur). La répétabilité est l'ancre : chaque run est indépendant mais comparable aux précédents.

#### **2. Candy Crush Saga (King)**
**Boucles observées** (via gameplay officiel YouTube + mechanics wikis) :
- **Minute 1** : swap deux bonbons, match = destruction + cascade. 3 matchs d'affilée = power-up (bombe visuelle). Chaque coup consomme un "move" (ressource limitée par niveau).
- **Minute 10** : joueur comprend que combiner des power-ups (bombes × gels × rayures) multiplie la destruction. Économie explicite : N moves donnés au start du niveau = limite dure. Événements éphémères : bonus timed si la cible est atteinte en temps record.
- **Heure 5** : Les niveaux deviennent arithmétiquement impossibles sans boosts (achetables). Le joueur rencontre un mur : niveau non pas par compétence, mais par ressources. Système "retry unlimited" avec boosts payants crée une fenêtre de frustration-engagement.
- **Endgame** : Fin du contenu = campagne infinie (booster → niveau → booster). Pas de "win state" au sens victoire permanente ; chaque niveau est une microépreuve. Pas de story-driven closure.

**Rétention** : Candy Crush alterne gratification immédiate (cascades visuelles) + frustration planifiée (impossible à trois moves) + soft paywall (boosts temporisent la frustration). Les events timed (24h challenges) impriment une cadence d'alerte push.

#### **3. Peglin (Red Cabin)**
**Boucles observées** (via Steam trailer + speedrun Twitch VOD) :
- **Minute 1** : joueur tire une bille dans une grille d'épingles (pachinko-like). Bille rebondit, détruit les ennemis par contact direct. Économie simple : une ammo par tir.
- **Minute 10** : joueur collecte des "relics" (upgrades passifs) et des "spells" (attaques chargées). L'arbre de progression émerge : chaque run est un build unique. Prestige system latent : run suivante démarre différemment selon les relic déjà acquis (meta-progression).
- **Heure 5** : Boss fights obligatoires tous les 4-5 tirs. Patterns attaquants = partie des régimes de compétence (déplacement prudent). Économie complexe : gestion de l'ammo + priorité des upgrades = stratégie mid-run. Peu d'assets répétés : chaque zone de 3-4 tirs apporte une thématique nouvelle (variété perçue).
- **Endgame** : Victory = boss final tombé. Meta-progression post-run (seed suivant plus difficile ou moins difficile selon performance). Aucune micro-transaction pendant run ; monétisation = cosmétiques + accès early access.

**Rétention** : Peglin force l'asymétrie de chaque run (build unique = expérience inédite). Absence de "grind obligatoire" ==> joueur contrôle cadence. Boss patterns donnent une sensation de progression tactique (découvrir la faiblesse = eureka).

| **Move economy** | Vitesse (accélération ≠ limite) | Ressource (N moves / niveau) | Ressource (1 ammo = 1 tir) |
| **Progression** | Vitesse croissante (exo) | Niveau → Niveau (linéaire) | Relic tree + meta-seed (stochastique) |
| **Win state** | `has_win_state: false` (marathon) | `has_win_state: false` (endless) | `has_win_state: true` (boss final) |
| **Rétention anchor** | Perfection motrice + highscore | Gratification + frustration timed | Asymétrie de build + découverte |
