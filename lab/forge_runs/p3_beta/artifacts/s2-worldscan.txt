J'analyse trois jeux représentant les genres progressifs et les systèmes de rétention éprouvés du studio :

### 1. **Cookie Clicker** (Idle/Incremental Game)

**Sources citées :**
- Wikipedia Cookie Clicker : https://en.wikipedia.org/wiki/Cookie_Clicker
- Official Site : https://cookieclicker.com/
- Console Release Article (May 2025) : https://www.prnewswire.com/news-releases/the-legendary-idle-game-cookie-clicker-is-coming-to-consoles-on-may-22-302456142.html

**Boucles d'engagement :**

| Horizon | Mécanique | Progression | Feedback joueur |
|---------|-----------|-------------|-----------------|
| **Minute 1** | Click cookie → gain 1 cookie/click | Immédiat : achat premier Cursor pour 15 coins, arrêt du clic | Visual : +1 cookie animé, son de click, compteur |
| **Minute 10** | 10 Cursors = 1 cookie/s passif ; apparition Golden Cookies aléatoires | Cursor → Farm → Mine ; upgrades **(Cursor x2 damage)** ; Golden Cookies : 7-10s window, +77 cookies/s ou +% click/s | Auto-idle commence ; rush Golden Cookies pour boost |
| **Heure 5** | 10+ buildings actifs (Farms, Factories, Banks) ; Ascension system (reset pour multiplicateur) | Économie passe à ~10k cookies/s ; nouveau building chaque 100-500 cookies ; résine = hardcap avant Ascension | Sensation de progression exponentielle ; décision d'Ascension (risk/reward) |
| **Endgame** | Ascensions répétées ; Grandmapocalypse événement ; nouvelles mécaniques (Prestige, Heralds) | Asymptote : progression ralentit → collecteurs finaux (250 buildings) ; pas de condition finale (marathon) | Optimisation meta vs gameplay relax ; tâche asymptotique |

**Retention answer :**
"Pourquoi revenir ? Progression visible et croissance exponentielle : chaque session, les bâtiments produisent plus → nouvelles achats → sensation de pouvoir croissant. Ascension = reset émotionnel mais reste d'un multiplicateur (prestige). Golden Cookies = tension minute-à-minute. **Pas d'état gagné** : le jeu reconnaît 'fin' en Ascensions multiples, mais rejeu toujours actif."

**Sources citées :**

- Hades Wiki How-to-Play : https://hades.fandom.com/wiki/How_to_play_guide_for_Hades

- YouTube Hell Mode Playthrough : https://www.youtube.com/watch?v=kV_-FnR5Mfk (Hades Hell Mode Part 8, Nov 2024)

**Boucles d'engagement :**

| Horizon | Mécanique | Progression | Feedback joueur |
|---------|-----------|-------------|-----------------|
| **Minute 1** | Start with Stygius (sword) ; tutorial biome Tartarus ; 2-3 weak enemies | Learn attack pattern + dodge ; first boon from Hermes (speed/dash) ; tutorial chamber victory | Fluid combat, immediate challenge, early boon choice |
| **Minute 10** | Complete 1-3 chambers (~10 min) ; 3-4 boons combinés (ex. Hermes Speed + Ares Damage) ; chamber rewards : coins, Poms | Experimentation : boon synergy emerges (build) ; door choices (fight/shop/repair) ; first damage taken vs boss incoming | Synergy moments ; early deck-building feel |
| **Heure 5** | 3 biomes cleared → Boss fight Elysium or Styx → reach final boss ; multiple Darkness/Keys farming ; 2-3 Mirror upgrades purchased between runs | Run becomes ~35-60 min ; die → retry with permanent meta-upgrades (Darkness spent) ; feel stronger each attempt even on loss | Replayability loop confirmed ; death = progress not setback |
| **Endgame** | Escape achieved → unlock true finale (reach Hades' wife) → 300+ boon combinations ; Pact of Punishment (escalating difficulty) ; Heat system (custom difficulty sliders) | Meta-currency (Darkness, Keys) unlocks new weapons, aspects, abilities ; Ascensions-like system (Pact Heat levels 1-32) ; long-tail content (lore reveals on runs) | Thousands of hour potential ; community speedrun/challenge culture |

**Retention answer :**
"Pourquoi revenir ? Chaque run crée une build unique via le RNG des boons : même boss affronté 30 fois joue différemment. Meta-progression (Darkness) fait chaque mort un pas avant, jamais un retour à zéro. Pact of Punishment offre escalade infinie de défi personnel. **État de victoire explicite** : échapper (classique) → vrai finale (lore), mais runs continuent. Variété des armes + boons = re-rejouabilité."

**Sources citées :**

- Slay the Spire Wiki - Victory Conditions : https://slay-the-spire.fandom.com/wiki/Act_4

- YouTube - A20 Heart Attempts : https://www.youtube.com/watch?v=OKLuhR2W5Xo (April 21 2024)

**Boucles d'engagement :**

| Horizon | Mécanique | Progression | Feedback joueur |
|---------|-----------|-------------|-----------------|
| **Minute 1** | Start with Ironclad ; opening hand = 5 cards (Strikes, Defends) ; enemy = 45 HP | First combat : play cards → damage enemy, block → take damage ; explore rooms ; first card offered as reward (pick 1 of 3) | Immediate deckbuilding : cards visible in hand ; tension = sparse deck |
| **Minute 10** | 2-3 combats done ; deck = ~8 cards (3-4 additions chosen) ; first elite fight choice offered | Synergy emerges (ex. Pump → Heavy Blade with +strength scaling) ; relic choice (passive bonus) ; first tough choice : take damage or skip elite | Deck curves : early weak → middle playable → decisions matter |
| **Heure 5** | Act 2-3 progressing ; deck stabilizing (~20-25 cards) ; 2-3 relics active (ex. Tough Bandages = block regen) ; bosses faced (Act 1-2 bosses, Act 3 boss incoming) | Deck archetype crystallizes (ex. "Strength deck" or "Scaling spells") ; potions available (one-time use in combat) ; shops allow card removal (critical optimizer choice) | Deck tightness vs breadth decision ; power scaling evident |
| **Endgame** | Beat Act 3 boss → choice : end run OR collect 3 colored keys for Act 4 (Heart, optional superboss 750 HP) | Victory = Beat Act 3 (standard) OR Heart (challenge) ; Ascension ranks (1-20 difficulty multipliers per character) ; if collecting keys = must beat Heart for "true ending" | Clear win condition ; escalation via Ascension system (ladder) |

**Retention answer :**
"Pourquoi revenir ? Chaque run crée une combinaison de cartes UNIQUE basée sur le RNG et les choix : 20k+ runs ne répètent jamais la même deck. Ascension (1-20) offre escalade de défi compétitive. Quatre personnages = mécaniques radicalement différentes. **État de victoire explicite** : Beat Acts 1-3 = win ; Heart = superboss optionnel. Ladder (Ascension) = replay valeur infinie."

## Architecture supposée & Briques candidates pour réutilisation

**Systèmes partagés observés :**
1. **Meta-progression découpée** (Hades/Spire) : run-based (échecs = progrès) vs Idle (gradient)
2. **RNG + Choix du joueur** (Spire/Hades) : variété structurée (boon pools, card drafts)
3. **Économie à couches** (tous) : ressource rapide (coins/click) + lente (meta-currency)
4. **Escalation progressive** (Spire/Hades) : difficulté modulable ou implicite
5. **Observable instantanément** (tous) : chiffres visibles (DPS, deck taille, boon count)

**Briques candidates import knowledge_base :**
- `idle_economy.yaml` : cascade de bâtiments, multiplicateurs, prestige
- `run_based_meta.yaml` : death = xp, meta-currency from runs
- `synergy_pool.yaml` : boons/cards, RNG weighted + player choice
- `ascension_ladder.yaml` : escalade symétrique de difficulté (Spire heat = Hades pact)

## Cadre d'architecture (Advisory)

Les trois jeux montrent des patterns de conception complémentaires :

- **Cookie Clicker** = système d'**économie passive cascade** : briques faibles → moyennes → fortes, avec multiplicateurs graduels. Idéal pour **progression sensation** (exponentielle).
- **Hades** = **rogue-lite meta-progression** : runs = échecs productifs, mort = progrès, boons = variété RNG contenude. Idéal pour **rejouabilité asymptotique**.
- **Slay the Spire** = **deck-building run-based** : synergies RNG + player skill, escalade via Ascension. Idéal pour **challenge progressive** et **optimisation communautaire**.

Pour p3_beta, les briques candidates prioritaires sont :
1. **Run-based meta-currency loop** (Hades pattern) : death ≠ loss, but xp
2. **Economy escalation** (Cookie Clicker pattern) : visible multiplicateurs
3. **Synergy-based RNG** (Spire pattern) : choix joueur + RNG contenu
